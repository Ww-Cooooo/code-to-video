# 审片与返修

## 分开记录三种检查

1. **技术核验**：视频能否解码，尺寸/时长/帧率是否正确，音轨是否存在，客观响度与峰值如何。
2. **视觉审查**：真正查看画面或连续片段，检查空间关系、构图、文字、节奏与转场。
3. **声音审听**：真正听到音频，判断内容、音色、衔接和声音层次。

任何一种都不替代另外两种。生成接触表不等于看过；文件里有音频不等于听过；没有听觉输入时不写“试听通过”。

## 先有针对性地看

代表帧覆盖每个镜头的进入、主要动作和可读停留。切镜和物体交接至少看前、当时、后；快速动作加密到足以分辨变化，不用统一每三秒取图去证明 0.3 秒转场。

例如：

```bash
python scripts/video.py preview my-film --out review-cut --dense 19.5:22:0.125
```

打开真实生成的 contact 图片。若仍看不清运动，播放局部片段或逐帧查看。不能只看脚本里写了正确公式就判定画面正确。

## 空间关系检查

对同一镜头中的主体，明确预期关系：

| 预期关系 | 需要看什么 |
| --- | --- |
| 分离 | 镜头变化后是否仍有可见间隔；背景线是否误读为连接 |
| 接触 | 接触点是否随物体移动，有没有悬浮、滑动或明显嵌入 |
| 包含 | 外壳透明度、遮挡和内外边界能否表达“在里面” |
| 生长/变形 | 原物体是否按设计保留；新结构是否误穿过旧物体 |
| 先后交接 | 前一对象何时退出，后一对象何时出现，中间是否突兀断开 |

不是禁止所有几何相交，也不是装一个碰撞库就能完成审片。画面关系必须符合创作意图。

### 来自实际制作的返修例子

一条“Agent 记忆”动画把记忆核和树干放在同一轴线上，生长段及片尾都保留球体，形成树干穿球的观感。编码和抽帧检查已运行，但第一次视觉审查仍漏掉了问题。

修正不是把球随便挪到角落：先让核向根部收缩消失，然后生长树；片尾不再复用错误组合。随后密集检查交接时段，并检查其他复用该场景的镜头。

迁移原则：反馈指向的往往是对象关系，而不是某个坐标参数。修改前先判断“保留什么关系”，再选择移动、遮挡、形变或时序。

## 其他常见缺陷

- 排版：中文缺字、字符被裁、英文标注太小、字幕与主体抢视线。
- 时间：文字刚出现就消失、镜头停太久、动作还没完成就切走。
- 光影：发光把主体烧成白团、暗部细节无法辨认、粒子争夺注意。
- 连续性：物体无故跳位置、跨镜头状态重置、摄像机穿过几何、随机噪声闪烁。
- 音频：未配置却声称有声、旁白被音乐盖住、结尾突然截断、短音轨被补静音后未说明。

## 用户指出问题时

先定位秒数和工程，保留认可部分。明确缺陷直接修；主观反馈的原意有多种解释时，按 [意图与范围判断](intent-and-scope.md) 说明差别并问清，再修改依赖答案的部分。可用推荐或现有画面帮助说明取舍；用户已授权比较草案时按该范围制作，不先选一个未确认的意思实施，也不把反复问卷当作修复。

修完复核受影响时段，以及复用同一对象或场景的其他镜头。不要每次无差别重测所有无关工程。新版本使用新文件名，报告改了什么、保留了什么、实际看了哪里。

## 交付前

对最终 MP4 执行 verify，而不是只验中间无声片。客观检测失败时报告输出，不隐藏或降格成成功。

明确列出尚未覆盖的审查，避免“全部检查通过”这种无法支撑的总括。用户最终认可当前作品，不自动等于认可所有未来作品沿用同一风格。
